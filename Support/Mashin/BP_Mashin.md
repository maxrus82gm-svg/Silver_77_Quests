# Цель

Сделать учебный транспорт на Blueprint:

- персонаж сможет садиться в машинку;
- управление будет передаваться Pawn-машине;
- корпус будет физическим объектом;
- колёса будут иметь точки подвески;
- позже колёса будут визуально крутиться;
- машинка будет вести себя ближе к вездеходу, а не к гоночной машине.

# Важные переменные

В процессе создания машинки будут использоваться переменные.

## DlinaPodveski

```text
Name: DlinaPodveski
Type: Float
Default Value: 160.0
```

`DlinaPodveski` — это длина подвески.

Она означает расстояние, на котором точка колеса ещё считается достаточно близкой к земле, чтобы подвеска могла работать.

Простыми словами:

```text
если расстояние от точки колеса до земли меньше DlinaPodveski,
значит подвеска может начать толкать корпус вверх
```

Пример:

```text
расстояние до земли = 137.32
DlinaPodveski = 160.0

137.32 < 160.0
значит колесо находится в зоне работы подвески
```

Важно:

В Unreal Engine расстояния обычно считаются в сантиметрах.

```text
1 Unreal Unit = примерно 1 см
```

# Шаг 1. Тип Blueprint

Машинку создаём как `Pawn`, а не как `Actor`.

Причина:

- `Pawn` может получать управление от `Player Controller`;
- в него проще “посадить” персонажа;
- `Actor` тоже можно двигать через Blueprint, но для управляемого транспорта `Pawn` подходит лучше.

Blueprint:

```text
BP_CubeCar
Parent Class: Pawn
```

# Шаг 3. Физика корпуса

Физику включаем именно на компоненте `Body`, потому что двигаться должен корпус машины.

Настройки `Body`:

```text
Simulate Physics = true
Mass = 800
Linear Damping = 0.8
Angular Damping = 3.0
```

`Linear Damping` — сопротивление линейному движению.  
Чем выше значение, тем быстрее объект теряет скорость и меньше скользит.

`Angular Damping` — сопротивление вращению.  
Чем выше значение, тем меньше объект крутится и переворачивается как юла.

Для вездехода полезно:

- не слишком маленький `Linear Damping`, чтобы не было ощущения льда;
- более высокий `Angular Damping`, чтобы корпус был устойчивее.

# Шаг 4. Точки колёс

Колёса сначала делаем не мешами, а точками.

Добавляем 4 компонента:

```text
Scene Component
Wheel_FL
Wheel_FR
Wheel_RL
Wheel_RR
```

Расшифровка:

```text
FL = Front Left
FR = Front Right
RL = Rear Left
RR = Rear Right
```

`Scene Component` — это не отдельная сцена, а пустая точка/трансформ внутри актора.  
Таких компонентов может быть сколько угодно.

Они нужны как:

- точки колёс;
- точки подвески;
- места для Line Trace;
- места приложения силы.

# Шаг 5. Важная заметка про иерархию

Если `Wheel_FL`, `Wheel_FR`, `Wheel_RL`, `Wheel_RR` являются дочерними компонентами `Body`, то их координаты считаются относительно `Body`.

Это называется `Relative Location`.

Важно учитывать масштаб родителя:

```text
Body Scale = 3.0 / 1.5 / 0.5
```

Если родитель масштабирован, дочерние точки могут визуально смещаться не так, как ожидается.

Правило:

```text
если компонент уехал не туда —
проверь Parent, Relative Transform и Scale родителя
```

Заметка:

Если точка колеса стоит внутри иерархии `Body`, её положение зависит от трансформа `Body`.

Если временно настраивать точку вне иерархии `Body`, позиционирование может казаться более понятным. Но для будущей физики точки колёс удобнее держать связанными с корпусом, чтобы они двигались вместе с машиной.

# Шаг 6. Примерные позиции точек колёс

Для корпуса с длиной `Scale X = 3.0` можно начать с таких значений:

```text
Wheel_FL: X = 140,  Y = -70, Z = -40
Wheel_FR: X = 140,  Y =  70, Z = -40
Wheel_RL: X = -140, Y = -70, Z = -40
Wheel_RR: X = -140, Y =  70, Z = -40
```

Эти значения можно подстроить визуально.

Главное:

- точки должны быть примерно у нижних углов корпуса;
- передние точки находятся по `+X`;
- задние точки находятся по `-X`;
- левая/правая сторона расходятся по `Y`;
- `Z` находится ниже корпуса.

# Шаг 7. Первая проверка подвески через Line Trace

Теперь проверим, что точка колеса может “видеть” землю под собой.

Пока делаем только для одного колеса:

```text
Wheel_FL
```

В `BP_CubeCar` в `Event Graph` на `Event Tick` собираем тестовый `Line Trace`.

Логика:

```text
Wheel_FL → Get World Location = Start
Start + Vector(0, 0, -120) = End
Line Trace By Channel
```

Настройки `Line Trace By Channel`:

```text
Trace Channel = Visibility
Draw Debug Type = For Duration
```

Что должно произойти:

- из точки `Wheel_FL` вниз будет рисоваться луч;
- если луч достаёт до земли, он покажет попадание;
- так мы проверяем будущую “подвеску”.

Важно:

`Line Trace` пока ничего не толкает и не двигает.  
Он только проверяет расстояние от точки колеса до земли.

Это первый шаг перед настоящей физикой подвески.

# Шаг 8. Создание нижней точки луча

Нужно получить две точки:

```text
Start = позиция Wheel_FL
End = позиция Wheel_FL ниже по Z
```

Для этого используем:

```text
Wheel_FL → Get World Location
```

`Return Value` от `Get World Location` — это позиция точки колеса в мире.

Дальше добавляем ноду сложения:

```text
Vector + Vector
```

Подключение:

```text
A = Get World Location от Wheel_FL
B = Vector(0, 0, -120)
```

Итог:

```text
End = Wheel_FL World Location + Vector(0, 0, -120)
```

Заметка:

Обычный выход `Get World Location` можно использовать сразу в нескольких местах.  
Не обязательно сразу сохранять его в переменную.

Например:

```text
Get World Location
        ├── Start в Line Trace
        └── V2 в Distance(Vector)
```

# Шаг 11. Проверка попадания в землю

Теперь нужно понять, реально ли луч попадает в землю.

У `Line Trace By Channel` есть выход:

```text
Return Value
```

Это `Boolean`:

```text
true  = луч во что-то попал
false = луч ни во что не попал
```

Добавляем:

```text
Branch
```

Подключение:

```text
Line Trace By Channel → Branch
Return Value → Condition
```

Для проверки можно добавить `Print String`:

```text
True  → Print String: Грунт есть
False → Print String: Нет контакта с землёй
```

Смысл:

```text
если True — подвеска видит землю
если False — подвеска не видит землю
```

# Шаг 12. Увеличение длины луча

Если луч рисуется, но `Return Value = false`, значит он может быть слишком короткий.

Изначально было:

```text
Vector(0, 0, -120)
```

Если этого мало, ставим:

```text
Vector(0, 0, -500)
```

То есть в ноде `Vector + Vector`:

```text
X = 0
Y = 0
Z = -500
```

После этого снова проверяем в игре.

Если появляется:

```text
Грунт есть
```

значит луч начал доставать до земли.

Заметка:

В нашем случае `-120` было мало, а `-500` нормально достало до земли.

# Шаг 13. Получение точки попадания

Теперь нужно узнать, куда именно луч попал.

От синего пина:

```text
Out Hit
```

у `Line Trace By Channel` добавляем:

```text
Break Hit Result
```

В `Break Hit Result` нас интересует:

```text
Impact Point
```

`Impact Point` — это точка, где луч коснулся земли.

Эта точка нужна, чтобы измерить расстояние от колеса до земли.

Логика:

```text
Line Trace By Channel
        ↓ Out Hit
Break Hit Result
        ↓ Impact Point
```

# Шаг 14. Измерение расстояния до земли

Добавляем ноду:

```text
Distance (Vector)
```

или:

```text
Vector Distance
```

Подключаем:

```text
V1 = Impact Point из Break Hit Result
V2 = Get World Location от Wheel_FL
```

Важно:

Если `V2` оставить равным `0, 0, 0`, расстояние будет считаться не от колеса, а от центра мира.  
Это неправильно.

Правильная схема:

```text
Distance(Vector)

V1 = Impact Point
V2 = Wheel_FL World Location
```

`Return Value` от `Distance(Vector)` можно вывести через `Print String`.

Пример результата:

```text
137.32
```

Это значит, что точка `Wheel_FL` находится примерно на 137 см над землёй.

# Шаг 15. Переменная DlinaPodveski

Теперь создаём переменную длины подвески.

В `BP_CubeCar` создаём переменную:

```text
Name: DlinaPodveski
Type: Float
Default Value: 160.0
```

Смысл:

`DlinaPodveski` — это максимальная рабочая длина подвески.

Если расстояние от точки колеса до земли меньше этой длины, значит подвеска может работать.

Пример:

```text
Distance до земли = 137.32
DlinaPodveski = 160.0
```

Проверка:

```text
137.32 < 160.0
```

Значит точка колеса находится в зоне работы подвески.

Позже мы будем использовать это для расчёта силы, которая будет толкать корпус машины вверх.

Важно:

Название переменной используем именно такое:

```text
DlinaPodveski
```

А не:

```text
SuspensionRestLength
```
