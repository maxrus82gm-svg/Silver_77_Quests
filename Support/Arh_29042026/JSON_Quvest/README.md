# Quest JSON Workshop

Локальный редактор для файлов с квестами и триггерами в формате JSON.

## Первая точка входа для нового Codex

Если к проекту подключается новый Codex-агент, сначала открыть:

- `P:\Silver_77_Quests\Documentation_DayZ_Qwest\11_AGENT_TASK_LOOP_зеркало.md`
- `P:\Silver_77_Quests\Documentation_DayZ_Qwest\12_START_зеркало.md`

## Что уже умеет

- импортировать существующий `.json`
- автоматически чинить часть типовых синтаксических проблем при импорте
- редактировать `quests` и `triggers` отдельными блоками
- требовать обязательную привязку каждого квеста к одному `trigger / NPC`
- управлять массивами `giveItems`, `objectives`, `rewards`, `questIds`, `npcLoadout`, `npcBackItems`
- валидировать связи между квестами и триггерами
- показывать живой `JSON Preview`
- экспортировать результат обратно в `.json`

## Как запустить

1. Для обычного запуска на Windows лучше использовать `start-editor.cmd`.
2. Если нужно, можно открыть и сам `index.html` в браузере.
3. Если редактор открыт через локальный сервер, можно нажать `Загрузить базу` и подтянуть `Silver_77_Quests.json` автоматически.
4. Если редактор открыт обычным двойным кликом как локальный файл, нажми `Импорт JSON` и выбери `Silver_77_Quests.json` вручную.
5. Меняй квесты и триггеры через формы.
6. Нажми `Экспорт JSON`, чтобы получить готовый файл.

`start-editor.cmd` нужен в том числе затем, чтобы окно с редактором старалось выходить на передний план после запуска.
При запуске через `start-editor.cmd` редактор также сразу создает резервную копию в `.local/Silver_77_Quests_BackUP.json`.
Дефолтные пути лежат в `editor-config.json`, а пользовательские переопределения сохраняются локально в `editor-config.local.json` и меняются прямо из интерфейса.

## Базовый файл

За основу редактора сейчас взят `Silver_77_Quests.json`. Его структура используется как основной ориентир для импорта, отображения и валидации.

## Логика привязки квестов

У каждого квеста теперь есть обязательное поле выбора `trigger / NPC`, который его выдает. Сам JSON при этом по-прежнему хранит связь через массив `trigger.questIds`, но редактор поддерживает эту связь автоматически.

## Режим подсчета количества

- Для `objectives` поле `useItemQuantity` переключает способ подсчета.
- `0` = считать каждый предмет / стак как `1`.
- `1` = суммировать внутреннее `quantity` предмета.
- Используй `1` для патронов, денег в стаках, `Firewood`, `WoodenStick`, воды, топлива и других quantity-предметов.
- Используй `0` для рыбы, ножей, банок, инструментов и других обычных предметов, где нужно считать именно штуки / стаки.

## Справочник стеков

- Отдельный локальный файл `item-stack-rules.json` хранит размеры стеков для классов предметов.
- Редактор показывает этот справочник в левом столбце и сохраняет его независимо от JSON квестов.
- Сам экспорт квестов этот справочник не засоряет: он нужен именно как база для будущих правил пересчета.

## Сохранение и резервная копия

- При запуске через `start-editor.cmd` редактор берет дефолтный конфиг из `editor-config.json`, применяет локальные переопределения из `editor-config.local.json`, копирует исходный файл в `backupPath`, а затем открывает рабочий JSON.
- Если редактор открыт через локальный сервер из запускателя, кнопка `Экспорт JSON` сохраняет изменения поверх файла по `savePath`.
- Если прямое сохранение недоступно, редактор автоматически откатывается к обычной выгрузке файла через браузер.

## Черновик редактора

- Во время работы редактор сохраняет текущее состояние в локальный файл `editor-draft.json`.
- При следующем запуске через `start-editor.cmd` этот черновик автоматически восстанавливается.
- После успешного прямого сохранения в основной JSON черновик очищается.
- `editor-draft.json` не должен храниться в git и используется только как локальное рабочее состояние.
