# Источники данных сервера

Справочник отвечает на два вопроса: где находится информация о мире и за что она отвечает. Он не копирует содержимое больших XML/JSON и не является самой картой.

## Статусы источников

- **Источник истины** — канонический файл конкретной системы в репозитории. Фактический runtime может отличаться, если серверный profile обновляется отдельно.
- **Server/custom snapshot** — сохранённая копия серверной конфигурации. Она полезна для анализа, но сама по себе не доказывает текущее состояние работающего сервера.
- **Vanilla/reference snapshot** — справочная копия mission или vanilla-структуры.
- **Внешний reference** — источник для сверки и исследования, который не управляет runtime проекта.

`DayZ_Server_Reference` создан как read-only справочный snapshot. В TASK 167 mission/env и профильные Danger Zones были сверены с фактическими серверными источниками. Snapshot остаётся копией на момент проверки и не становится автоматически актуальным после будущих изменений runtime.

### Сопоставление Hazard / Visual / Audio

MedicalAttention используется как Hazard geometry, Night — как отдельный Visual component, Sound — как отдельный Audio component. Из 78 активных MedicalAttention-зон у 71 ближайший Night-center находится в пределах 5 м, у 68 ближайший Sound-center — в пределах 5 м, у 68 в пределах 5 м найдены оба компонента. Это полезный пространственный кандидат, но близость сама по себе не доказывает логическую идентичность: уверенность повышалась только при совпадающем названии/комментарии.

Сохранённая внешняя карта:

- [DayZ Interactive Map](https://dayz.xam.nu/)

Внешняя карта помогает визуальной сверке, но не является источником истины для custom-конфигурации сервера.

## Правила будущего извлечения

1. Сначала определить статус и версию snapshot.
2. Читать только нужный source-файл и только поля, необходимые выбранному слою.
3. Для составных данных сохранять связи: `events.xml` → `cfgeventspawns.xml` → `cfgeventgroups.xml`.
4. Не смешивать координатные схемы: DayZ vector обычно использует X/Y/Z, а некоторые плоские zone-конфиги называют вторую координату `Y`, хотя по смыслу это координата карты Z.
5. Не выводить отсутствующие параметры из похожего мода или соседнего файла.
6. Сохранять путь и статус источника у каждой нормализованной записи.
7. Большие `types`, `mapgroup` и cluster-файлы обрабатывать адресно или механическим parser, а не повторным полным ручным анализом.

## Известные ограничения snapshot

- Mission/env и три profile-source Danger Zones подтверждены на дату TASK 167, но repository snapshot не обновляется автоматически после будущих изменений сервера.
- Происхождение классов `Mutant_AoD_Tushkano*` и `Mutant_AoD_Forester1` не доказано; похожие имена классов из других PBO не считаются подтверждением.
- Некоторые source-файлы используют отличную от UTF-8 кодировку. Например, `Mission/CustomSpawnPlayerConfig/Sets.c` корректно читается как Windows-1251; это свойство исходника, а не повод автоматически его перекодировать.
- Пустые или выключенные конфиги фиксируют поддерживаемую структуру, но не создают активный объект карты.
