# Карта мира сервера

Документ описывает фундамент будущей интерактивной карты. Самой карты, готового нормализованного dataset и автоматики обновления пока нет.

Карта предназначена для визуального анализа игрового мира и проектирования gameplay. Она должна помогать строить квесты, зоны и события, сохраняя происхождение каждого отображённого объекта.

Источники данных для этой системы учитываются отдельно от требований к будущей карте.

## Задачи карты

- показывать расположение и плотность значимых объектов и опасностей;
- помогать оценивать маршруты, расстояния и возможные обходы;
- показывать пересечения зон и конфликтующие системы;
- выявлять пустые, перегруженные и плохо связанные участки мира;
- давать человеку и агенту одинаковое структурированное представление;
- помогать проектировать квесты без переноса полных квестовых сценариев в карту.

## Будущие слои

- NPC;
- Traders;
- Infected;
- специальные заражённые;
- Mutants;
- Animals и собаки, если они представляют gameplay-угрозу;
- Toxic / Contaminated / Effect Zones;
- `Silver_77_Zones`;
- другие опасные или значимые gameplay-зоны;
- spawn и activation points, когда они полезны для анализа;
- Migration spawn, route, target и связанные области;
- другие подтверждённые категории, найденные позднее.

Квесты не становятся самостоятельным полным слоем. Карта может показывать существующий quest NPC или trigger как мировой объект, но диалоги, objectives, зависимости и награды остаются в квестовой системе.

## Нормализованная запись

Будущий формат должен поддерживать запись следующего смысла. Это концептуальная модель, а не утверждённая JSON-схема.

| Поле | Смысл |
|---|---|
| ID | Устойчивый идентификатор нормализованного объекта |
| Название | Читаемое имя объекта или зоны |
| Категория | NPC, Trader, Infected, Mutant, Animal, Effect Zone, Migration и другое |
| Источник данных | Точный repository path и при необходимости исходный ID/секция |
| Происхождение | Vanilla, current server/custom, собственный mod или внешний reference |
| Статус источника | Источник истины, рабочая копия или reference snapshot |
| Enabled | Активна ли запись, если source предоставляет такой параметр |
| Координаты | X/Z и Y, когда высота действительно нужна |
| Геометрия | Point, circle, square/rectangle, polygon, cylinder, route или другой подтверждённый тип |
| Радиус или границы | Только значения, реально предоставленные источником |
| Количество | Число существ, объектов или spawn slots, если оно задано |
| Описание | Краткое назначение и gameplay-смысл |
| Дополнительные параметры | Detection/aggro radius, inner/outer radius, lifetime, chance, spawn limits и другие подтверждённые значения |

Запись должна сохранять исходные значения без домысливания. Если источники используют разные системы координат или названия осей, нормализация обязана явно хранить правило преобразования.

## Представление геометрии

- Одиночный объект показывается точкой.
- Круговая зона показывается центром и окружностью.
- Прямоугольная, polygon или cylinder zone сохраняет свою исходную форму.
- Migration route показывается линией через ordered route points, отдельно от spawn и target.
- Относительные child offsets event group нельзя отображать как мировые координаты без базовой event position и подтверждённого преобразования.
- Y хранится там, где важны высота, вертикальные пределы или точное размещение объекта. Для плоского анализа основными координатами остаются X/Z.

## Фильтры интерфейса

Будущий интерфейс должен иметь checkbox-фильтры:

- Показать всё;
- NPC;
- Traders;
- Infected;
- специальные заражённые;
- Mutants;
- Animals и собаки;
- Toxic / Effect Zones;
- `Silver_77_Zones`;
- spawn и activation points;
- Migration;
- другие будущие категории.

Для радиусов и границ нужен отдельный переключатель. Пользователь должен иметь возможность оставить точки и объекты видимыми, скрыв окружности и контуры зон.

При необходимости слой может получить дополнительные фильтры по enabled/status, vanilla/custom/mod и конкретному source snapshot. Это будущее расширение, а не реализованная функция.

## Информационная карточка

При выборе точки, маршрута или зоны должна открываться компактная карточка:

- название и ID;
- категория и тип объекта;
- координаты;
- радиус или форма;
- количество, если применимо;
- основные подтверждённые gameplay-параметры;
- короткое описание;
- источник данных и его статус.

Карточка не должна показывать параметр, которого нет в источнике. Например, detection/aggro radius нельзя вычислять только по визуальному размеру территории или подменять радиусом spawn/cleanup.

## Использование человеком и агентом

Человек использует карту, чтобы визуально сравнивать маршруты, опасные области, плотность объектов и свободные участки.

Агент использует нормализованные записи, чтобы:

- оценить длину и риск маршрута квеста;
- понять, какие существующие NPC находятся по пути;
- проверить пересечения `Silver_77_Zones`, contaminated areas и Migration;
- не придумывать отсутствующие точки и параметры;
- назвать source-файлы, на которых основано предложение.

## Будущий цикл обновления

1. Получить новый snapshot с рабочего сервера.
2. Механическим diff определить добавленные, изменённые и удалённые source-файлы.
3. Передать агенту только изменившиеся данные и необходимый контекст.
4. Интерпретировать смысл изменений.
5. Создать, обновить или удалить соответствующие нормализованные записи.
6. Обновить визуальные точки, маршруты и зоны.
7. Проверить результат и принять новый snapshot как следующую базу.

Diff выполняет сравнение файлов. AI интерпретирует значение изменений. Нейронка не должна каждый раз заново анализировать весь сервер или вручную выполнять побайтовое сравнение.

## Границы текущего этапа

В TASK 166 не создаются:

- Web-карта и её HTML/JS/CSS;
- нормализованный JSON или база данных;
- parser больших source-файлов;
- diff-автоматика;
- baseline/incoming каталоги;
- новые runtime-модули;
- точки и зоны, которых нет в подтверждённых источниках.

Документ фиксирует требования для будущей реализации.
