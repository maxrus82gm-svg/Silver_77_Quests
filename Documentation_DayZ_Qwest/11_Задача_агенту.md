## RECOMMENDED ARCHITECTURE

1. Вариант B: отдельная Map-вкладка и дополнительное синхронизируемое окно; полные module editors сохраняются.
2. Один authoritative editor state и владелец записи на источник; Map получает spatial projections.
3. Доменные фасады выполняют команды и validation; adapter не становится универсальным editor/persistence API.
4. Active view, edit module, selection, camera и reference layers разделены.
5. Manual Save публикует данные; autosave сохраняет draft. Нужны revision/hash и защита от stale writes.
6. Detached Map — mirror, при потере owner edits блокируются; второй Workshop не должен становиться параллельным writer.
7. Quest связывается с существующей EXTERNAL ACTIVATION; внутренние параметры Migration остаются в Migration.
8. Zones владеет территорией/exposure, Medicine — заболеванием. Внешние источники read-only до отдельного whitelist write-back.

## REJECTED / WEAK OPTIONS

Не рекомендованы независимые карты-редакторы в каждом модуле, Map-first перестройка Quest, самостоятельное Map-приложение на данном этапе, JSON как UI-шина и detached как второй writer. Отложены универсальный plugin framework, terrain service, live telemetry и cross-module skeleton creation.

## FIRST VERTICAL SLICE

Одна существующая Migration GROUP: минимальная форма координат и Map над одним state, существующие spawn/route/target points, Y confirmation, dirty, cancel, undo/redo, validated Save и conflict/draft recovery. Без новых групп, route add/delete/reorder, полного Migration Editor, detached окна и runtime bridge. В документе указаны предполагаемые файлы, исключения, acceptance criteria и ручной сценарий проверки.

## QUEST / MAP CONCLUSION

Карта показывает уникальные triggers/NPC и роли выбранного quest; role blocks не равны отдельным NPC. Deep link использует questId/role/triggerId, не индекс. Objectives, rewards, giveItems, диалоги и equipment остаются в Quest. Проекция маршрута не навязывает порядок Completion и не доказывает проходимость.

## MIGRATION / MAP CONCLUSION

GROUP — blueprint, EVENT/ACTIVATION — логические связи. Различены центры и смысл route activation, hold и return radii; X/Z drag не обнуляет Y. Runtime принимает DayZInfected-наследников; произвольные животные/мутанты автоматически не поддерживаются.

## QUEST -> MIGRATION CONCLUSION

Рекомендована EXTERNAL ACTIVATION. Bool true не гарантирует spawn: возможен chance miss; busy не является очередью. Момент запуска, idempotency, scope и поведение quest при отказе требуют отдельной runtime-задачи. Save в Workshop не запускает Migration.

## ZONES CONCLUSION

Canonical Zones JSON ещё не утверждён; lighting prototype не является постоянным world-source. Map не должна навязать схему Zones или вернуть логику болезни из Medicine в Zones.

## DETACHED MAP CONCLUSION

Сначала одноконный editing/save slice. Затем адресный message protocol, snapshot/revision, request deduplication, owner epoch, reconnect и блокировка edits при разрыве. Требуется browser prototype; runtime-проверка detached в TASK 171 не выполнялась.

## ADAPTER / STATE MODEL CONCLUSION

Доменный store — источник редактируемого состояния, canonical file — сохранённый результат, MapFeature — производная проекция. Capabilities, provenance, source/world identity и runtime observations разделены. Unknown fields и исходная семантика не должны теряться при write-back.
