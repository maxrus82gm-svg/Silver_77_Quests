TASK 153 — Эталонный MigrationConfig.json в Support готового мода

ЦЕЛЬ

Сделать так, чтобы после обычной сборки Silver_77_Migrate в корне готового мода, рядом с его обычной структурой, всегда существовала папка:

Этот файл нужен пользователю как всегда доступный актуальный эталон конфигурации для ручного копирования/сравнения с:

$profile:Silver_77_Migrate/MigrationConfig.json

ЧИТАТЬ

Обязательно:

- Silver_77_Migrate_server/config/README_RU.md

Также сначала определить фактический существующий build/packaging workflow Silver_77_Migrate_server.

ГЛАВНОЕ РЕШЕНИЕ

Единственным source of truth для эталонного конфига остаётся:

Silver_77_Migrate_server/config/MigrationConfig.json

Не создавать второй независимо редактируемый MigrationConfig.json.

При каждом обычном build/package этот исходный файл должен автоматически копироваться в:

<корень готового мода>/Support/MigrationConfig.json

То есть Support-копия всегда должна соответствовать версии конфига, из которой собирался данный мод.

Support должен находиться СНАРУЖИ PBO и быть обычной доступной папкой готового мода.

Пользователь должен иметь возможность открыть готовый мод и сразу вручную забрать:

Support/MigrationConfig.json

RUNTIME

Не менять существующую runtime-логику.

Мод по-прежнему читает рабочий конфиг только из:

$profile:Silver_77_Migrate/MigrationConfig.json

Support/MigrationConfig.json:
- не является runtime-файлом;
- не должен автоматически загружаться вместо profile;
- не должен автоматически перезаписывать существующий profile;
- служит только эталонной/reference-копией для пользователя.

Если runtime MigrationConfig.json отсутствует, существующая логика его создания остаётся без изменений.

BUILD / PACKAGING

Сначала установить, как сейчас фактически собирается Silver_77_Migrate_server.

Если в проекте уже существует build/post-build/package step:
- добавить туда минимальное копирование canonical MigrationConfig.json в Support готового мода.

Не создавать параллельную вторую систему сборки, если существующую можно минимально расширить.

Если текущая сборка выполняется только внешним GUI и в проекте вообще нет места, куда безопасно добавить автоматический post-build step:
- не имитировать выполненную автоматизацию;
- остановиться со статусом BLOCKED;
- точно описать текущий способ сборки и какой минимальный hook/шаг нужен для автоматического копирования.

Не помещать Support-копию внутрь Silver_77_Migrate_server.pbo вместо требуемой внешней папки.

ПРОВЕРКА РЕЗУЛЬТАТА

После тестовой сборки структура должна концептуально выглядеть так:

- MigrationConfig.json доступен как обычный файл вне PBO;
- Support/MigrationConfig.json соответствует canonical Silver_77_Migrate_server/config/MigrationConfig.json;
