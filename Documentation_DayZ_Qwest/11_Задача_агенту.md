- Точные класс, функция, сигнатура и result type оставлены `TBD`.

EVENT ID / SCENARIO ID / RUNTIME GROUP ID:
- `eventId` — предпочтительный стабильный внешний контракт для Quest System и других инициаторов.
- `scenarioId` — внутренний blueprint ID migration scenario, известный event-системе.
- `runtimeGroupId` — динамический ID созданной группы; Quest System никогда его не хранит.
- Один `eventId` сначала может запускать один scenario, а позже — несколько scenarios или другие части world event без изменения внешней ссылки.

QUEST INTEGRATION:
- Будущий quest action / trigger сможет запросить `Запустить World/Migration Event` по `eventId` после подтверждённого NPC/item/action/zone либо другого quest condition.
- Quest JSON-поле, Quest Editor UI, checkbox/dropdown и обработка результата не утверждались и остаются отдельной задачей.

OTHER ACTIVATION SOURCES:
- Тот же entry point должны использовать `QUEST`, `ZONE`, `CALENDAR / SCHEDULER`, `RANDOM`, `ADMIN` и другие server-side источники.
- Scheduler и zone logic только определяют `eventId`; они не спавнят infected и не содержат migration AI logic.

REPEAT PROTECTION / MULTIPLAYER:
- Зафиксирована будущая централизованная проверка `NOT_FOUND`, disabled, active instance, repeat/cooldown/one-shot, завершения и лимитов runtime groups.
- Почти одновременное выполнение одного условия несколькими игроками не должно автоматически размножать один глобальный event без явного правила.
- Multiplayer scope, repeat protection и точный результат вызова остаются `TBD`.

PERFORMANCE:

- Постоянный polling Migration Manager, scan мира или infected для bridge не предусматривается.
