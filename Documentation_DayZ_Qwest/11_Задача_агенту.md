Это рабочий shell-документ текущего агентского цикла.

Он нужен для того, чтобы хранить:

- текущую задачу в `БЛОКЕ 1`;
- последний `AGENT REPORT` в `БЛОКЕ 2`;
- последний `REVIEW / STATUS` в `БЛОКЕ 3`;
- короткую карту чтения `SplitDoc`.

Правила:

- Постоянные правила: `Documentation_DayZ_Qwest/12_Старт_агента.md`
- Тематические правила: `Documentation_DayZ_Qwest/20_SplitDoc` по матрице ниже

# БЛОК 1 — ТЕКУЩАЯ ЗАДАЧА

TASK 159 — Создать read-only справочную копию актуальных серверных данных DayZ для проектирования квестов

ЦЕЛЬ

Создать внутри репозитория `Silver_77_Quests` отдельную справочную копию актуальных файлов реального DayZ-сервера, которые нужны для дальнейшего анализа:

- экономики и редкости предметов;
- мест спавна животных и заражённых;
- динамических событий;
- заражённых/опасных зон;
- географии и координат объектов;
- спавнов игроков;
- доступных NPC и существ;
- кастомных построек/объектов;
- торговой экономики, если Trader используется на сервере.

Эта задача НЕ меняет сервер.
Нужно только СКОПИРОВАТЬ существующие файлы с сервера в репозиторий.

ЧИТАТЬ

Обязательно:

- `Documentation_DayZ_Qwest/11_Задача_агенту.md`
- `Documentation_DayZ_Qwest/12_Старт_агента.md`
- `Documentation_DayZ_Qwest/20_SplitDoc/SERVER_PROFILE_RULES.md`
- `Documentation_DayZ_Qwest/20_SplitDoc/ENCODING_RULES.md`

ИСХОДНЫЕ ДАННЫЕ

Использовать реальный установленный сервер и активную mission/server-конфигурацию, доступные на этой машине.

Не угадывать путь.
Сначала определить фактически используемую сервером mission-папку и связанные с ней конфиги.

Если существует несколько mission/profile/config-копий, брать именно активную серверную версию и явно указать использованный источник в AGENT REPORT.

DESTINATION

Создать в корне репозитория:

`DayZ_Server_Reference/`

Основные mission-файлы складывать в:

`DayZ_Server_Reference/Mission/`

с сохранением исходной относительной структуры каталогов.

Дополнительные plain-text конфиги сервера/модов при необходимости складывать в тематические подпапки внутри:

`DayZ_Server_Reference/Server_Custom_Config/`

Не смешивать эти файлы с рабочим кодом Quest или Migration.

СКОПИРОВАТЬ ИЗ АКТИВНОЙ MISSION

Если существуют:

1. Central Economy:

- `db/types.xml`
- `db/events.xml`
- `db/globals.xml`
- `db/economy.xml`

2. Основные CE/config-файлы:

- `cfgeconomycore.xml`
- `cfgspawnabletypes.xml`
- `cfgrandompresets.xml`
- `cfglimitsdefinition.xml`
- `cfgeventspawns.xml`
- `cfgplayerspawnpoints.xml`
- `cfgenvironment.xml`
- `cfggameplay.json`

3. Environment:

- всю папку `env/` с сохранением структуры.

4. География / здания:

- `mapgrouppos.xml`
- `mapgroupproto.xml`
- `mapgroupcluster*.xml`, если существуют;
- `mapclusterproto.xml`, если существует;
- `mapgroupdirt.xml`, если существует.

5. Дополнительная экономика:

Прочитать активный `cfgeconomycore.xml`.

Если он подключает дополнительные пользовательские XML/CE-файлы, скопировать также эти реально используемые файлы с сохранением их относительной структуры.

Не ограничиваться только базовым `types.xml`, если сервер фактически подключает дополнительные economy-файлы.

ДОПОЛНИТЕЛЬНЫЕ СЕРВЕРНЫЕ КОНФИГИ

Если они доступны как обычные JSON/XML/TXT/CFG/C-файлы вне PBO и их назначение однозначно понятно, дополнительно скопировать конфиги, описывающие:

- собак;
- химер;
- других кастомных существ;
- их spawn/territory/позиции;
- NPC и их позиции;
- доступные NPC classname, если они содержатся в серверных plain-text конфигах;
- кастомные здания, лагеря и объекты;
- Object Spawner / custom object placement;
- Trader economy / цены и категории, если Trader реально используется.

Для Trader нужны именно актуальные конфиги экономики/цен.
Не копировать ненужные бинарные файлы мода.

ВАЖНО

В этой задаче НЕ нужно:

- распаковывать PBO;
- копировать целиком Workshop-моды;
- копировать `.pbo`, `.bisign`, ключи или бинарники;
- анализировать и перерабатывать квесты;
- менять `18_Идеи_Квестов.md`;
- менять Quest JSON;
- менять Quest Client/Server;
- менять `Silver_77_Migrate_server`;
- подключать `DayZ_Server_Reference` к runtime;
- изменять серверные конфиги;
- форматировать или перекодировать исходные файлы.

КРИТИЧЕСКОЕ ПРАВИЛО

Источник на сервере — READ ONLY.

Разрешена только операция COPY:

SERVER SOURCE
→
`Silver_77_Quests/DayZ_Server_Reference/...`

Запрещено:

- редактировать источник;
- перемещать источник;
- переименовывать источник;
- удалять источник;
- сохранять источник заново;
- нормализовать encoding;
- форматировать XML/JSON;
- заменять серверный файл копией из репозитория.

Копия должна быть байтово идентична источнику.

БЕЗОПАСНОСТЬ

Не переносить в Git:

- пароли;
- RCon/password данные;
- Steam/API credentials;
- приватные ключи;
- signing keys;
- admin credentials;
- player databases;
- persistence игроков;
- логи;
- crash dumps;
- backup-архивы;
- персональные данные игроков.

Если нужный конфиг одновременно содержит секретные данные — не копировать его целиком.
Указать это в `PROBLEMS / NOT COPIED`.

Не делать ручную "очистку" такого файла без отдельной задачи.

ЕСЛИ ЧЕГО-ТО НЕТ

Отсутствующий файл не является ошибкой задачи.

Не создавать искусственный аналог.

В отчёте разделить:

- COPIED;
- NOT FOUND;
- NOT COPIED FOR SAFETY;
- NEEDS SEPARATE EXTRACTION / PBO, если нужная информация находится только внутри мода/PBO.

ПРОВЕРКИ

После копирования:

1. Для каждого скопированного файла подтвердить совпадение source/destination.
   По возможности использовать hash/byte comparison.

2. Убедиться, что исходные серверные файлы не изменялись.

3. Убедиться, что в `DayZ_Server_Reference` не попали:
   - credentials;
   - ключи;
   - player data;
   - логи;
   - PBO/bisign;
   - ненужные бинарники.

4. Проверить `git status`.

Ожидаемые изменения:

- новая папка `DayZ_Server_Reference/...`;
- стандартные изменения агентского task loop:
  - `Documentation_DayZ_Qwest/11_Задача_агенту.md`;
  - `Documentation_DayZ_Qwest/20_SplitDoc/TASK_HISTORY.md`.

Не делать commit/push — Git контролирует пользователь.

BUILD / RUNTIME

Сборка модов не требуется.
Запуск сервера не требуется.
Обновлять серверные или клиентские моды не требуется.

AGENT REPORT

Помимо стандартного отчёта обязательно указать:

- фактический source path активной mission;
- destination;
- список/категории скопированных файлов;
- количество файлов;
- какие дополнительные файлы были найдены через `cfgeconomycore.xml`;
- какие NPC/creature/building/Trader конфиги удалось найти;
- `NOT FOUND`;
- `NOT COPIED FOR SAFETY`;
- что осталось только внутри PBO/модов и поэтому не копировалось;
- результат byte/hash comparison;
- подтверждение: SERVER SOURCE UNCHANGED;
- подтверждение: NO BUILD / NO RUNTIME CHANGES / MODS UPDATE NOT REQUIRED.

После успешного выполнения обновить AGENT REPORT, TASK_HISTORY и очистить БЛОК 1 по стандартным правилам.
