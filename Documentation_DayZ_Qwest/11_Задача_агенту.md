6. РЕДАКТИРОВАНИЕ КООРДИНАТ В ФОРМЕ
============================================================

Форма должна менять тот же Migration state, который используется Map projection.

Допускается редактирование существующих числовых X/Y/Z значений.

============================================================
7. Y POLICY
============================================================

Это важная часть первого slice.

Если X/Z точки были изменены:

- старое Y не обнулять;
- старое Y не заменять случайным значением;
- старое Y сохранять;
- точку пометить как `Y требует подтверждения`.

Это относится и к:

- редактированию X/Z через форму;
- drag на Map.

Для каждой перемещённой точки должен быть понятный UI-status.

Например:

Y: 104.073151
Статус: требуется подтверждение после перемещения X/Z

Добавить явное действие:

«Подтвердить Y»

или эквивалентный понятный control.

Это подтверждение пока является editor-state metadata и НЕ добавляется в MigrationConfig JSON.

Не добавлять новые runtime JSON-поля.

После явного подтверждения статус точки становится подтверждённым.

Если после этого X/Z снова изменились — confirmation снова сбрасывается.

Terrain-height service в TASK 174 НЕ создавать.

============================================================
8. DIRTY / RESET
============================================================

После любого реального изменения coordinates state становится dirty.

Во вкладке Migration должен быть видимый статус:

Сохранено / Без изменений

или

Есть несохранённые изменения

Но поскольку TASK 174 не умеет Save, формулировка должна ясно говорить, что изменения находятся только в памяти.

Добавить действие:

«Сбросить изменения»

Оно должно восстановить загруженный baseline config и spatial state без повторного запуска страницы.

После reset:

- координаты возвращаются к исходным;
- dirty=false;
- Y confirmation возвращается к baseline;
- undo/redo очищаются;
- Map немедленно получает baseline projection.

Не вызывать запись файла.

============================================================
9. UNDO / REDO
============================================================

Добавить минимальные Undo / Redo для spatial coordinate edits.

Обязательные требования:

- изменение формы = одна понятная history operation;
- один завершённый Map drag = одна history operation;
- десятки pointermove во время одного drag НЕ должны превращаться в десятки Undo;
- Undo возвращает coordinates;
- Redo повторяет coordinates;
- Y-confirmation state также должен восстанавливаться согласованно.

История может быть организована per-group либо корректно адресовать `groupId`.

Переключение GROUP не должно уничтожать уже внесённые in-memory изменения.

Не реализовывать универсальную command framework для всего Workshop.
Нужен только минимальный механизм этого slice.

============================================================
12. DRAG MIGRATION POINTS НА MAP
============================================================

Migration points должны быть draggable.

Только:

X
Z

Map drag НЕ меняет Y.

Во время drag:

- point визуально следует за курсором;
- state/form получает новые X/Z;
- Y сохраняется;
- Y confirmation становится false / requires confirmation.

После pointerup:

- фиксируется ОДНА undo transaction.

Если пользователь нажал Escape во время активного drag:

- вернуть point к coordinates начала этого drag;
- не создавать undo transaction для отменённого drag;
- корректно восстановить dirty относительно остальных изменений.

Map pan должен продолжать работать при drag пустого места.

Drag Migration point не должен случайно запускать pan карты.

MedicalAttention остаётся read-only.
