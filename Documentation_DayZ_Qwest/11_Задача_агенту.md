Зафиксировать следующий смысл.

------------------------------------------------------------
ОБЩАЯ СЦЕНА
------------------------------------------------------------

Игрок идёт через лес, поле, дорогу или другую территорию и входит в специальную encounter-зону.

Событие должно ощущаться неожиданным:

- заражённые появляются не прямо перед глазами игрока;
- предпочтительно появляются со стороны леса, кустов, рельефа или другой визуально скрытой области;
- после появления быстро выходят к игроку;
- находятся в агрессивном / атакующем поведении;
- во время выхода и атаки периодически слышны крики заражённых.

Основная атмосфера:

сначала игрок может услышать угрозу, затем увидеть выбегающих заражённых и вынужден быстро реагировать.

------------------------------------------------------------
ПЕРСОНАЛЬНОЕ МАСШТАБИРОВАНИЕ ПО ИГРОКАМ
------------------------------------------------------------

Очень важное решение:

не считать только общее количество игроков и не создавать одну безадресную общую пачку.

Encounter должен концептуально работать ПО ПОДХОДЯЩИМ ИГРОКАМ.

Пример идеи:

- один подходящий игрок -> его собственный набор примерно 2–3 заражённых;
- два подходящих игрока -> для каждого может быть создан собственный набор;
- три игрока -> аналогично для каждого подходящего игрока.

Конкретное количество пока НЕ фиксировать как окончательный баланс.
`2–3` оставить как пример исходной идеи.

------------------------------------------------------------
ЗАЩИТА ОТ ДВОЙНОГО НАЗНАЧЕНИЯ
------------------------------------------------------------

Это обязательная часть идеи.

Если на конкретного игрока уже создан / назначен активный набор заражённых от этой Ambush Zone / encounter-сессии, повторно создавать второй набор на этого же игрока нельзя.

То есть условно:

Player A уже имеет активных attackers от этого encounter
-> новый комплект для Player A не создаётся.

Player B ещё не имеет своего активного encounter-набора
-> Player B может получить собственных attackers.

При двух игроках должно быть возможно:

Player A -> свой набор заражённых
Player B -> свой набор заражённых

Но один и тот же игрок не должен получить второй набор только потому, что повторно пересёк trigger или система выполнила ещё одну проверку.

Это концепция per-player encounter ownership / assignment.

Не утверждать конкретную техническую реализацию этого ownership.

------------------------------------------------------------
AI / AGGRO
------------------------------------------------------------

Желаемое поведение:

созданный для игрока набор должен первоначально ориентироваться / агриться на этого игрока.

Но честно отметить:

реальная возможность надёжно удерживать конкретного DayZ infected на конкретном player target требует отдельного prototype / исследования AI.

Не обещать жёсткий target-lock без проверки.

Важно зафиксировать дизайн:

не допускать повторного spawn-набора для игрока, который уже считается обслуживаемым текущим encounter.

------------------------------------------------------------
АКТИВАЦИЯ / ДЕАКТИВАЦИЯ ЗОНЫ
------------------------------------------------------------

Ambush Zone не обязана срабатывать при каждом входе всегда.

Предусмотреть концептуально:

- случайную / вероятностную активацию;
- активное и неактивное состояние;
- после успешного срабатывания зона должна временно отключаться;
- cooldown до следующего возможного события;
- позднее возможна повторная активация;
- повторная активация также может иметь chance/random logic.

Точные поля, проценты и таймеры сейчас НЕ определять.

Не вводить сейчас конкретные JSON names вроде `activationChance`, если они не утверждены.
Их можно упомянуть только как будущие концепции, не контракт.

------------------------------------------------------------
ЗАЩИТА ОТ СПАМА
------------------------------------------------------------

Зафиксировать будущую необходимость:

- не запускать encounter повторно каждую секунду, пока игрок стоит внутри зоны;
- не создавать новую волну одному игроку, пока его предыдущий encounter ещё активен;
- предусмотреть общий maximum / safety cap для больших групп игроков;
- предусмотреть cooldown/deactivation зоны.
