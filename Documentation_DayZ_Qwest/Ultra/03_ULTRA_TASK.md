Спроектировать один непротиворечивый workflow для трёх режимов:

1. `EXECUTOR: CODEX`
2. `EXECUTOR: ULTRA`
3. `EXECUTOR: CODEX + ULTRA`

## Канонический контракт режимов

### EXECUTOR: CODEX

- Codex читает body БЛОКА 1 и REQUIRED-контекст.
- Самостоятельно выполняет содержательную TASK.
- Ultra не запускает; `03` и `04` не использует.
- Применяет стандартный Codex lifecycle, если TASK прямо его не отключает.

### EXECUTOR: ULTRA

- Codex — только технический dispatcher.
- Читает body и REQUIRED лишь для сборки полного payload; содержательную TASK не выполняет.
- Полностью пересобирает `03`, не использует старое содержимое, включает задачу, фактическое состояние, правила, ограничения, входные данные, критерии, пути и достаточный REQUIRED-контекст.
- Проверяет существование и непустоту `03`.
- Вызывает только каноническую пару `03 + 04`.
- После возврата не открывает и не читает `04`, не ищет строки, не анализирует результат, не применяет patch и не продолжает TASK вместо Ultra.
- Возвращает только технический статус и останавливается.

### EXECUTOR: CODEX + ULTRA

- Codex остаётся основным исполнителем.
- Определяет отдельную подзадачу Ultra, полностью формирует новый непустой `03`, вызывает `03 + 04`.
- После успешного вызова обязан прочитать `04`, сопоставить с отправленным payload, проверить полноту, соответствие и выводы.
- Только после проверки использует результат и при необходимости применяет его в scope основной TASK.

Если `EXECUTOR` отсутствует, неизвестен или header повреждён, режим не угадывать: выполнение и dispatch не начинать. При `AUTO-DELEGATION: OFF` Codex не меняет назначенного исполнителя.
