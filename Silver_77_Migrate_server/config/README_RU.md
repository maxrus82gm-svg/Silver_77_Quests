# Настройки Silver_77_Migrate_server

В каталоге находятся исходные образцы трёх runtime-конфигов. После сборки server-only мода рабочие копии создаются в `$profile:Silver_77_Migrate/`.

JSON-файлы не поддерживают комментарии. Описание параметров находится только в этом README.

## MigrationEvent.json

Глобальный конфиг одного migration-события. Только он управляет общим временем запуска и погодой для всех включённых групп.

- `enabled` — включает событие: `1` — включено, `0` — выключено. Пример: `1`.
- `eventDelaySeconds` — задержка от инициализации мода до начала погодного перехода, в секундах. Пример: `30.0`.
- `weatherEnabled` — включает общий погодный предвестник: `1` — использовать погоду, `0` — запустить группы после `eventDelaySeconds` без изменения погоды. Пример: `1`.
- `weatherTransitionSeconds` — длительность плавного перехода overcast, fog и rain к заданным значениям, в секундах. Группы создаются после завершения этого времени. Пример: `180.0`.
- `weatherOvercast` — целевая облачность от `0.0` до `1.0`. Пример: `1.0` означает сплошную облачность.
- `weatherFog` — целевая плотность тумана от `0.0` до `1.0`. Пример: `0.8`.
- `weatherWindMagnitude` — требуемая скорость ветра в метрах в секунду. Пример: `0.0`; vanilla API фактически применяет безопасный минимум `0.1 m/s`.
- `weatherRain` — целевая интенсивность дождя от `0.0` до `1.0`. Пример: `0.0` оставляет грозу без дождя.
- `weatherStormEnabled` — включает нарастающую грозу: `1` — включено, `0` — storm density остаётся `0`. Пример: `1`.
- `weatherStormDensity` — финальная частота/плотность грозы от `0.0` до `1.0`. Пример: `0.8`.
- `weatherStormThreshold` — минимальная облачность, выше которой vanilla может показывать молнии, от `0.0` до `1.0`. Пример: `0.8`.
- `weatherStormTimeoutSeconds` — минимальный интервал между молниями, в секундах. Пример: `30.0`.
- `weatherStormRampSeconds` — длительность нарастания storm density в конце погодного перехода, в секундах. Пример: `60.0`; при transition `180.0` ramp идёт с 120-й по 180-ю секунду перехода.

## MigrationScenario_001.json и MigrationScenario_002.json

Каждый файл описывает одну независимую migration-группу. Погодных настроек и собственной задержки запуска в актуальной scenario-схеме нет.

- `enabled` — включает конкретную группу: `1` — создавать, `0` — пропустить. Пример: `1`.
- `scenarioId` — уникальный текстовый идентификатор группы, используемый в состоянии infected и серверных логах. Примеры: `MIGRATION_TEST_001`, `MIGRATION_TEST_002`.
- `infectedCount` — количество infected в этой группе. Пример: `10`.
- `infectedTypes` — список vanilla class names infected. Если infected больше, чем элементов списка, классы повторяются по кругу. Пример: `ZmbF_JournalistNormal_Blue`.
- `spawnPosition` — центр появления группы как массив координат `[X, Y, Z]` в метрах мира. Пример Scenario 002: `[12874.942383, 130.418289, 13074.552734]`.
- `targetPosition` — центр конечной точки маршрута как массив `[X, Y, Z]`. Пример Scenario 002: `[13091.167969, 121.727158, 13051.032227]`.
- `spawnFormationSpacing` — базовый интервал сетки между infected возле spawn, в метрах. Пример: `4.5`.
- `spawnFormationJitter` — максимальное случайное отклонение каждой spawn-позиции по X/Z в обе стороны, в метрах. Пример: `0.5` означает диапазон примерно от `-0.5` до `+0.5`.
- `targetFormationSpacing` — базовый интервал сетки индивидуальных целей возле target, в метрах. Пример: `4.5`.
- `targetFormationJitter` — максимальное случайное отклонение индивидуальной цели по X/Z в обе стороны, в метрах. Пример: `0.5`.
- `logIntervalSeconds` — интервал диагностической записи состояния infected этой группы, в секундах. Пример: `10.0`.

## Совместимость старого Scenario 001

В runtime-файле `MigrationScenario_001.json`, созданном версией TASK 131, могут оставаться `spawnDelaySeconds` и weather-поля. Мод не удаляет и не перезаписывает их, но после TASK 132 они считаются legacy и игнорируются. Активные задержка и погода читаются только из `MigrationEvent.json`.

Runtime schema обновляется только add-only: существующие пользовательские значения и порядок полей не сбрасываются, malformed JSON не заменяется defaults, повторная проверка без новых полей не меняет файл.
