# БЛОК 1 — ТЕКУЩАЯ ЗАДАЧА

## TASK 121 — Добавить видимый справочник предметов в правую часть редактора

### 1. Цель задачи

Нужно добавить в веб-редактор квестов видимую правую панель справочника предметов.

Справочник нужен как рабочая шпаргалка при настройке наград, выдаваемых предметов, предметов для сдачи и других item/className-полей.

Справочник должен быть виден прямо в редакторе, справа от основной области редактирования.

### 2. Что нужно реализовать

Добавить отдельный справочник предметов с двумя колонками:

1. `className`
2. `Описание на русском`

Пример строки:

* `BandageDressing` — `Бинт`
* `SmallStone` — `Маленький камень`
* `BeanieHat_Brown` — `Коричневая вязаная шапка`

Справочник должен храниться отдельно от основного квестового JSON.

Рекомендуемый новый файл:

`JSON_Quvest/item-class-reference.json`

Рекомендуемая структура:

{
"version": 1,
"items": []
}

Важно: справочник не должен записываться внутрь `Silver_77_Quests.json` и не должен влиять на runtime-логику мода.

### 3. UI-требования

В редакторе справа добавить постоянную панель:

Название панели:

`Справочник предметов`

Внутри панели:

* поле поиска;
* таблица из двух колонок:

  * `Classname`
  * `Описание`
* кнопка добавления новой строки;
* кнопка сохранения справочника;
* возможность удалить строку;
* возможность редактировать обе колонки прямо в таблице или через простые input-поля.

Видимость таблицы:

* примерно 20 строк по высоте;
* если строк больше — вертикальный scroll внутри панели;
* основная страница редактора не должна становиться неудобной из-за длинного справочника.

Правая панель должна быть удобной на обычном desktop-экране. Если ширины экрана не хватает, допустимо аккуратно переносить панель ниже основной области, но на нормальной ширине она должна быть справа.

### 4. Поиск

Поиск должен работать как live-filter.

Требования к поиску:

* без учёта регистра;
* искать по колонке `className`;
* искать по колонке `descriptionRu`;
* частичное совпадение достаточно;
* поиск обновляется сразу при вводе;
* пустая строка поиска показывает все элементы.

Примеры:

Если пользователь пишет:

`бинт`

должны находиться строки, где русское описание содержит `бинт`.

Если пользователь пишет:

`би`

должны находиться строки вроде:

* `Бинт`
* `Бибик`
* `Бинар`
* другие описания, где есть подстрока `би`.

Если пользователь пишет:

`band`

должны находиться className вроде:

* `BandageDressing`
* `Armband_Red`

Логика поиска по смыслу:

* привести запрос к lowercase;
* привести `className` к lowercase;
* привести `descriptionRu` к lowercase;
* проверить `includes`.

### 5. Удобство работы с className

Минимальное требование:

* className должен быть легко копируемым из таблицы.

Желательное поведение, если это можно сделать без риска сломать редактор:

* клик по className копирует значение в буфер обмена;
* если в редакторе сейчас активно поле `className`, клик по className из справочника вставляет его в это активное поле.

Если автоподстановка требует рискованной переделки архитектуры — не делать её в этой задаче. Тогда оставить только безопасное копирование className.

### 6. Backend/API редактора

Добавить в локальный сервер редактора API для справочника.

Рекомендуемые endpoints:

* `GET /api/item-reference`
* `POST /api/item-reference`

Поведение:

* `GET /api/item-reference` возвращает текущий справочник;
* если файла `item-class-reference.json` нет — вернуть пустую структуру:
  {
  "version": 1,
  "items": []
  }
* `POST /api/item-reference` сохраняет справочник в `JSON_Quvest/item-class-reference.json`;
* перед сохранением проверить, что JSON корректный;
* сохранять UTF-8 без BOM;
* не создавать лишние файлы, кроме самого справочника.

### 7. Разрешённые файлы

Можно менять только файлы редактора:

* `JSON_Quvest/server.ps1`
* `JSON_Quvest/app.js`
* HTML/CSS-файлы редактора внутри `JSON_Quvest`, если они реально существуют и используются
* можно создать новый файл:

  * `JSON_Quvest/item-class-reference.json`

Если стили находятся внутри HTML или JS, править тот файл, где они реально находятся.

### 8. Запрещено менять

Не менять серверную runtime-логику мода:

* `Silver_77_Quests_Server/scripts/4_World/QuestServerManager.c`
* любые файлы в `Silver_77_Quests_Server`, кроме случаев, если это не runtime, но в этой задаче сервер мода трогать не нужно
* любые файлы в `Silver_77_Quests_Client`
* основной квестовый JSON `JSON_Quvest/Silver_77_Quests.json`, кроме если он нужен только для чтения при проверке
* player progress/runtime profile files
* PBO/addons/build output
* сторонние папки и моды

Не делать:

* `git pull`
* `git push`
* `git reset`
* `git clean`
* `git checkout`
* создание PBO
* запуск Addon Builder
* массовый рефакторинг
* переименование существующих файлов без необходимости

Git контролирует пользователь.

### 9. Важные ограничения

Задача должна быть небольшой и точечной.

Не менять архитектуру квестов.

Не менять формат основного quest JSON.

Не менять логику наград, `itemQuantity`, `setItemQuantity`, `quantity`, ammo stack, completion, reward delivery.

Справочник — это только инструмент редактора.

### 10. Проверки после выполнения

После изменений выполнить доступные проверки:

1. Проверить JS:

`node --check JSON_Quvest/app.js`

2. Проверить PowerShell syntax/parse для `server.ps1`.

3. Проверить JSON справочника:

`JSON_Quvest/item-class-reference.json` должен быть валидным JSON.

4. Проверить, что сервер редактора запускается.

5. Проверить в браузере:

* справа появилась панель `Справочник предметов`;
* можно добавить строку;
* можно ввести `className`;
* можно ввести русское описание;
* можно сохранить;
* после перезагрузки редактора строки остаются;
* поиск `би` находит строки по русскому описанию;
* поиск `band` находит строки по className;
* таблица показывает примерно 20 строк и дальше скроллится;
* основной редактор квеста не сломан.

6. Проверить, что `Silver_77_Quests.json` не меняется от редактирования справочника.

7. Проверить, что в diff нет лишних сторонних файлов и папок.
