# Возможности Silver_77_Quests

## Общая идея

`Silver_77_Quests` - система квестов для DayZ, разделённая на клиентскую и серверную часть.

Клиентская часть отвечает за UI, журнал, подсказки и отправку запросов.

Серверная часть отвечает за основную логику: выдачу квестов, проверку условий, сдачу предметов, награды и сохранение прогресса игроков.

## Структура модов

- `Silver_77_Quests_Client` - клиентский мод для игроков.
- `Silver_77_Quests_Server` - серверный приватный мод.
- Основная настройка квестов выполняется через JSON в профиле сервера.

Запуск:

```bat
-mod=@Silver_77_Quests_Client
-serverMod=@Silver_77_Quests_Server
```

## Настройка через JSON

Основной рабочий конфиг:

```text
profiles\Silver_77_Quests\Silver_77_Quests.json
```

Через JSON можно настроить:

- список квестов;
- названия и описания;
- повторяемость;
- задержку до повторного взятия;
- предметы, выдаваемые при взятии;
- цели квеста;
- частичную сдачу предметов;
- награды;
- NPC/триггеры;
- спавн видимого NPC на точке квеста;
- одежду, предмет в руках и предметы за плечами у NPC;
- радиус зоны NPC;
- точку наведения на NPC;
- цепочки и последовательность квестов.

Если JSON уже создан в профиле сервера, дефолтный JSON из PBO его не перезаписывает. Для изменения рабочего конфига нужно редактировать именно профильный JSON или удалить его для пересоздания.

После изменения JSON нужно перезапустить сервер.

## Параметры квеста

Каждый квест имеет:

- `id` - уникальный ID квеста.
- `name` - название квеста.
- `description` - описание задания.
- `repeatable` - можно ли повторять квест.
- `cooldownSeconds` - задержка до повторного взятия.
- `requiresPrevious` - один обязательный предыдущий квест.
- `requiredQuestIds` - список обязательных выполненных квестов.
- `giveItems` - предметы при взятии квеста.
- `objectives` - цели квеста.
- `rewards` - награды.

## Последовательность квестов

Можно делать цепочки квестов.

Простой вариант:

```json
"requiresPrevious": "quest_medic_1"
```

Расширенный вариант:

```json
"requiredQuestIds": [
  "quest_medic_1",
  "quest_medic_2",
  "quest_medic_3",
  "quest_hunter_medic_1"
]
```

Квест нельзя взять, пока все квесты из `requiredQuestIds` не были выполнены хотя бы один раз.

Для повторяемых квестов повторное взятие не сбрасывает доступ к следующим квестам, если квест уже был завершён раньше.

## Предметы при взятии квеста

Через `giveItems` можно выдать игроку предметы при принятии квеста.

Пример:

```json
"giveItems": [
  {
    "className": "HuntingKnife",
    "quantity": 1,
    "spawnOnGround": false
  }
]
```

Если `spawnOnGround` равен `false`, мод сначала пытается положить предмет в инвентарь.

Если предмет не помещается, он может появиться на земле возле игрока.

## Цели квеста

Сейчас основной тип цели - принести предметы.

Пример:

```json
"objectives": [
  {
    "type": "item",
    "className": "Carp",
    "quantity": 6,
    "removeOnComplete": true,
    "useItemQuantity": false,
    "allowPartialTurnIn": true
  }
]
```

Поля цели:

- `type` - тип цели, сейчас используется `item`.
- `className` - класс предмета DayZ.
- `quantity` - нужное количество.
- `removeOnComplete` - удалять ли предметы при сдаче.
- `useItemQuantity` - считать внутреннее количество предмета, а не штуки.
- `allowPartialTurnIn` - разрешить частичную сдачу.

## Частичная сдача

Квест можно настроить так, чтобы игрок сдавал предметы частями.

Например:

- нужно принести `Carp x6`;
- игрок сдаёт 2;
- потом сдаёт ещё 2;
- потом сдаёт ещё 2;
- квест завершается только после полного количества.

Сданный прогресс сохраняется.

## Награды

Через `rewards` можно выдавать предметы за завершение квеста.

Пример:

```json
"rewards": [
  {
    "className": "Ammo_12gaPellets",
    "quantity": 100,
    "spawnOnGround": false
  }
]
```

Сейчас `quantity` у награды означает количество создаваемых предметов или стаков.

Если вся награда не помещается в инвентарь, лишнее должно появиться на земле рядом с игроком.

## NPC и триггеры

NPC/триггер задаётся в JSON.

Пример:

```json
{
  "id": "fisherman_trigger",
  "position": [13092.814453, 117.007767, 13084.485352],
  "radius": 2.0,
  "focusHeight": 1.2,
  "focusRadius": 1.0,
  "questIds": ["quest_fisherman_1"],
  "hintText": "[F] Поговорить",
  "spawnNpc": true,
  "npcClassName": "SurvivorM_Mirek",
  "npcPosition": [13092.814453, 117.007767, 13084.485352],
  "npcOrientation": [215.0, 0.0, 0.0],
  "npcLoadout": [
    "FlatCap_BrownCheck",
    "HuntingJacket_Brown",
    "Jeans_Blue",
    "WorkingGloves_Brown",
    "HikingBootsLow_Black"
  ],
  "npcHandsItem": "FarmingHoe",
  "npcBackItems": ["HuntingBag", "Izh43Shotgun"]
}
```

Поля триггера:

- `id` - уникальный ID триггера.
- `position` - координаты.
- `radius` - радиус зоны взаимодействия.
- `focusHeight` - высота точки наведения над позицией.
- `focusRadius` - радиус виртуальной точки наведения.
- `questIds` - список квестов у этого NPC.
- `hintText` - текст подсказки.
- `spawnNpc` - спавнить ли видимого персонажа на сервере.
- `npcClassName` - ванильный класс персонажа.
- `npcPosition` - позиция NPC; если пусто, используется `position`; если заполнено, наведение работает по NPC.
- `npcOrientation` - поворот NPC.
- `npcLoadout` - одежда и снаряжение.
- `npcHandsItem` - предмет в руках.
- `npcBackItems` - предметы за плечами/на спине.

## Наведение на NPC

Меню диалога открывается не просто по нахождению в зоне.

Игрок должен:

- находиться в радиусе триггера;
- смотреть на виртуальную точку NPC;
- нажать `F`.

Это помогает разделить действия:

- поднятие предметов рядом с NPC;
- открытие меню диалога с NPC.

Если подсказка появляется слишком низко или слишком строго, можно настроить:

- `focusHeight` - выше или ниже точка наведения;
- `focusRadius` - больше или меньше зона попадания взглядом.

## UI

Есть меню NPC с квестами.

В меню видно:

- список квестов;
- статус квеста;
- можно ли взять;
- можно ли сдать;
- можно ли внести часть предметов;
- описание;
- цели;
- сданный прогресс;
- награды;
- список обязательных предыдущих квестов.

Меню NPC закрывается по кнопке закрытия и по `ESC`.

## Журнал квестов

Есть журнал активных квестов.

В журнале:

- показываются активные квесты;
- работает скролл;
- журнал закрывается по `ESC`.

## Серверная логика

Основная логика находится на сервере.

Сервер проверяет:

- можно ли взять квест;
- выполнены ли обязательные предыдущие квесты;
- активен ли квест;
- завершён ли квест;
- прошёл ли cooldown;
- хватает ли предметов для сдачи;
- можно ли сдать часть предметов;
- можно ли завершить квест;
- какие предметы удалить;
- какую награду выдать;
- какой прогресс сохранить.

Клиент не решает важные вещи сам, а только показывает UI и отправляет запросы.

## Возможности серверной части

Серверный мод `Silver_77_Quests_Server` держит приватную часть логики и запускается через `-serverMod`.

Сервер сейчас умеет:

- создавать рабочую папку `$profile:Silver_77_Quests`;
- создавать дефолтный `Silver_77_Quests.json`, если файла ещё нет;
- не перезаписывать существующий рабочий JSON;
- хранить версию конфига (`version = 2`);
- мягко мигрировать старый конфиг и добавлять новые NPC-поля без полной замены файла;
- нормализовать старые JSON, где нет новых массивов или параметров;
- сохранять конфиг через прямой `JsonSerializer + OpenFile` с понятными логами ошибок;
- повторно попытаться сохранить конфиг, если объект конфига в памяти есть, а файла в профиле нет;
- загружать квесты и триггеры из профильного JSON;
- спавнить видимых ванильных персонажей на точках квестов;
- настраивать для NPC класс, позицию, поворот, одежду, предмет в руках и предметы за спиной;
- делать заспавненных NPC неуязвимыми;
- отправлять клиенту актуальный конфиг и прогресс игрока через RPC;
- принимать RPC-запросы на взятие и сдачу квеста;
- проверять условия квестов только на сервере;
- сохранять прогресс игроков по SteamID;
- выдавать стартовые предметы при взятии квеста;
- удалять предметы-цели при сдаче;
- выдавать награды за завершение;
- если предмет не помещается в инвентарь, создавать его рядом с игроком;
- вести диагностические логи `[Silver_77_Quests]` для проверки запуска, загрузки JSON и сохранения.

Для серверной сборки важен Addon Builder prefix:

```text
Silver_77_Quests_Server
```

Если серверный PBO собрать с prefix `Silver_77_Quests`, PBO может собраться успешно, но серверные скрипты не подхватятся. Признаки: в RPT нет `MissionServer.OnInit called`, нет `QuestServerManager initialized`, рабочий JSON не создаётся.

## Сохранение прогресса

Прогресс игроков сохраняется по SteamID.

Для каждого игрока хранится:

- статус квеста;
- время последнего завершения;
- прогресс частичной сдачи по целям.

## Уже проверено в игре

- Разделение на клиентский и серверный мод работает.
- Русский текст отображается.
- NPC-меню открывается.
- Журнал открывается.
- Скролл в журнале работает.
- Журнал закрывается по `ESC`.
- NPC-меню закрывается по `ESC`.
- Частичная сдача работает.
- Накопление предметов работает.
- Баг раннего завершения накопительных квестов исправлен.
- Подсказка и `F` завязаны на наведение на NPC.

## Что пока не реализовано как отдельные типы целей

- Убийство зомби, животных или NPC.
- Посещение зоны.
- Диалоговые ветки с выбором ответа.
- Репутация и фракции.
- Ограничения по роли, уровню или группе.
- Случайные награды.
- Выбор одной награды из нескольких.
- Таймерные задания.

## Что уже можно собирать из текущих возможностей

На текущей версии можно делать не только простые задания "принеси предмет", но и более длинные сценарии:

- разовые сюжетные квесты, которые игрок проходит один раз;
- повторяемые квесты с задержкой до повторного взятия;
- ежедневные или полусуточные задания через `cooldownSeconds`;
- накопительные задания, где предметы сдаются частями;
- цепочки квестов через `requiresPrevious` и `requiredQuestIds`;
- финальные квесты, которые открываются только после нескольких предыдущих заданий;
- несколько квестов у одного NPC;
- несколько NPC с разными наборами квестов;
- квесты со стартовыми предметами, например выдать нож, сумку или инструмент при принятии;
- квесты с большим количеством наград, где лишние предметы падают рядом с игроком;
- разные визуальные образы NPC через одежду, предмет в руках и предметы за спиной;
- отдельную настройку точки наведения на каждого NPC, чтобы `F` не мешала поднимать предметы рядом.

Примеры сценариев:

- фермер просит постепенно сдать `PotatoSeed x50`, а награда выдаётся только после полного количества;
- рыбак выдаёт нож, просит принести `Carp x6` и принимает рыбу частями;
- медик открывает финальное задание только после выполнения всей цепочки предыдущих квестов;
- торговец держит несколько повторяемых заказов на разные предметы с разными cooldown;
- NPC может быть просто точкой выдачи квестов или полноценным видимым персонажем на сервере.

## Возможные доработки на будущее

Если развивать мод дальше, логичные следующие направления:

- добавить отдельную кнопку `ВНЕСТИ ПРЕДМЕТЫ`, если кнопка `СДАТЬ КВЕСТ` будет путать игроков на накопительных целях;
- показывать красивые названия предметов вместо `className`;
- добавить иконки предметов в цели и награды;
- добавить новые типы целей: убийства, посещение зоны, разговор с NPC, таймер;
- добавить расширенные награды: случайная награда, выбор одной награды, репутация, деньги или фракционные очки;
- добавить ограничения доступа к квесту по роли, группе, фракции, уровню или whitelist;
- добавить админские команды для сброса прогресса, тестовой выдачи предметов и проверки статуса игрока;
- добавить серверную горячую перезагрузку JSON без полного перезапуска сервера;
- добавить отдельные диалоговые ветки с вариантами ответа и разными последствиями;
- усилить защиту клиентской части, чтобы клиент получал только данные, нужные для отображения UI.

## Важные ограничения текущей версии

- Отдельный тип цели сейчас только `item`; убийства, зоны и диалоги можно описать текстом, но сервер пока не считает их отдельной механикой.
- Рабочий JSON в профиле сервера не обновляется автоматически после изменения дефолтного JSON внутри PBO.
- После изменения `profiles\Silver_77_Quests\Silver_77_Quests.json` сервер нужно перезапустить.
- Клиент получает конфиг для отображения UI, но принятие квестов, сдача предметов, удаление предметов, награды и сохранение прогресса проверяются на сервере.
- При добавлении новых полей в JSON нужно учитывать старые конфиги и при необходимости добавлять нормализацию/миграцию на сервере.
